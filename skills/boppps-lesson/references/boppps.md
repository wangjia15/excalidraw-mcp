# BOPPPS 教学设计

BOPPPS 是加拿大 ISW（Instructional Skills Workshop）提出的课堂结构，六个环节：

| 环节 | `stage` | 作用 | 45 分钟参考时长 | 常用活动 |
|---|---|---|---|---|
| B 导入 Bridge-in | `b` | 引起兴趣、建立与旧知/生活的联系 | 3–5 | 真实故障/新闻/提问、反差演示、短视频、"你遇到过…吗" |
| O 目标 Objective | `o` | 说清本节课结束后学生**能做什么** | 1–2 | 2–4 条可测量目标（布鲁姆动词） |
| P1 前测 Pre-assessment | `p1` | 摸底，调整讲解深浅 | 3–5 | 2–3 道选择/判断、举手、在线投票、猜输出 |
| P2 参与式学习 Participatory Learning | `p2` | 主体，讲练结合 | 25–30 | 讲解 + 演示 + 配对讨论 + 动手编码 + 案例分析，每 8–10 分钟一次活动 |
| P3 后测 Post-assessment | `p3` | 检验目标是否达成 | 4–6 | 与目标一一对应的小测、改错、口述解释、完成小任务 |
| S 总结 Summary | `s` | 归纳、布置作业、预告下节 | 2–3 | 思维导图回顾、一句话总结、作业与拓展 |

90 分钟（两节连上）：B 5、O 2、P1 5、P2 60（中间安排一次课间）、P3 10、S 5–8。

## 目标（O）的写法

用"学生能 + 可观察的动词 + 内容 + 条件/标准"：

- 记忆/理解：说出、列举、解释、区分
- 应用：使用、编写、配置、计算
- 分析/评价：比较、诊断、判断、选择
- 创造：设计、实现、改进

✗ "了解 Spring MVC 的原理" → ✓ "能画出一次请求经过 DispatcherServlet 的 5 个步骤"

教案中把目标分为 **知识 / 能力 / 素养** 三类，每条编号 O1、O2…，P3 的每道题注明检验哪条目标。

## 幻灯片结构（一讲约 14–22 页）

```
封面
B  分隔页 → 1–2 页导入（问题/案例/图片）
O  分隔页 → 1 页目标（bullets 或 kv）
P1 分隔页 → 1–2 页前测题（callouts ask）
P2 分隔页 → 6–12 页：概念 → 图解(Mermaid/图片) → 代码 → 活动页 → 小结，循环 2–3 个知识点
P3 分隔页 → 1–2 页后测题 / 任务
S  分隔页 → 1 页总结（flow 或 kv）+ 1 页作业与预告
```

- 分隔页：`{"type":"stage","stage":"p2","title":"参与式学习","badge":"28 分钟"}`。
- 环节内容页都写 `stage`，六点进度会高亮该环节。
- `badge` 写在分隔页（整个环节时长）；内容页上只在活动页用 `act`（如"配对讨论 · 3 分钟"）。
- 前测答案和后测答案写在 `notes` 和教案里，不放正面。

## 活动设计速查

| 活动 | 时长 | 幻灯片写法 |
|---|---|---|
| 思考—配对—分享 | 3–5 | `act:"配对讨论 · 4 分钟"`，`callouts:[{kind:"ask",text:"…"}]` |
| 猜输出/找 Bug | 3 | `code` + `callouts:[{kind:"ask",text:"这段代码输出什么？"}]` |
| 动手练习 | 5–10 | `act:"动手 · 8 分钟"`，`bullets` 写步骤（①②③），`callouts task` 写验收标准 |
| 概念对比 | 2–3 | `vs` |
| 流程排序 | 3 | 打乱的 `bullets`，`notes` 写正确顺序 |
| 投票/举手 | 1–2 | `bullets` 写选项 A–D |
